# 设计探针：决策总结

## 一、核心结论

**最要命的是 P1——轴纯度只有声明、没有事实层。** 整个采样协议建立在“这个维度是一维有序连续轴”上，但当前靠声明。这与粗选层“lineage/contrast 靠用户声明”是同一个病：证据链每一环都停在声明上。P4/P5/P7 是结论强度问题，**P1 是结论是否成立的问题**，所以先补代理，再谈实测。

撤回一处误判：生成器空不是缺陷（协议立法前提 writer ≠ evaluator，生成归 skill），真正的缺口是“skill 生成能否满足受控扰动契约从未验证”。

## 二、方案收敛：AST 变更集

试过五条路，结论：

| 方案          | 能做                  | 不能做              |
| ----------- | ------------------- | ---------------- |
| 像素比对        | 异常筛（扰动没发生/锁被破坏）     | 判轴（标量距离≠序关系）     |
| 正则抽取        | 抽声明值，代理第一环          | 抽的是声明，须渲染交叉验证    |
| LLM 声明轴     | 生成侧提议拆词             | 当裁判（不可复现，认词不认代理） |
| 用户授权        | 项目级预算/情境分配          | 判轴是否成立、代表偏好      |
| **AST 变更集** | **锁的正确代理：变了哪些种类变量** | 验轴（种类数≠轴数）；验序    |

**最终收敛到 AST**，因为前端改动本质是变量变化，AST 可回归、可版本化，比正则稳、比像素有向。

## 三、用户授权的精确定位（本次修正重点）

**用户授权是项目级的，只回答一个问题：这个项目值不值得花采样预算探这个维度。**

它**不代表**三件事：

1. **不代表用户偏好该维度** —— 问法是“这个项目需要更抽象还是更具体”（情境），不是“你喜欢抽象吗”（偏好）。协议立法前提1 禁问偏好不禁问情境。
2. **不代表该轴成立** —— 轴是否一维有序连续，由代理判，不由授权判。
3. **不代表该轴合适** —— 授权说的是“这个项目里这个维度值得探”，不是“这个维度是好轴/合适的轴”。合适性属于事实层，归代理。

**授权的真实作用**：给“不确定”态一个合法去处。AST 只能判绝对轴、绝对非轴，剩下大量“不确定”（一变量多轴、多变量一轴、映射不严格）——探哪些、先探哪个，只有项目需求能回答。授权把它变成有方向的探索性频谱采样，不插值。

**授权的边界（写死）**：

- 只发 `exploratory / spectrum_only` 凭证，插值接口拒收；
- 不替代锁验证（DOM 逐字节 + AST 变更集照跑）；
- 不替代序性验证（授权后采样排不出序，仍降级自由变体 + 台账记“授权但未证实有序”）；
- 预设回退，不变成“必须成功”的压力。

## 四、三层证据 + 三态判定

### 三层证据

1. **锁验证**：DOM 逐字节（渲染层）+ AST 变更集（源码层）。锁不住 → 重生成，不进轴判决。
2. **轴判定**：AST 变更集按结构化命名映射到轴。
3. **序性验证**：抽声明值验单调 → 渲染侧交叉验证 → 步长过 JND。

**前提**：变量命名必须结构化（`--sat` 而非 `--c1`），否则映射不到轴，方案退化为数量判据。变量→轴映射表是结构化、可版本化、可回归的声明。

### 三态判定（只判“绝对”与“不确定”）

- **绝对轴（严格 1:1）**：变更集严格映射到单一轴 + 序性单调 + 过 JND → 发“已证轴”凭证，**唯一可插值**。
- **绝对非轴**：映射到 ≥2 轴（串维）/ 无法映射（评价词、未拆合称、无语义命名）/ 序性不单调 → 按 3.0 拒收，降级自由变体，归因可写“轴是假的”。
- **不确定**：能映射但非严格 1:1 → 发“探索轴”凭证，**仅供频谱采样，禁止插值**；用户授权决定是否花预算探。

## 五、判断器约束

- **有回归用例才有资格当证据层**：R1–R5 五个已知结论跑一遍必须复现。
- 输出不是布尔，是三条路由：过 / 拒收 / 降级自由变体。
- 采样失败回退写死：降级 + 台账记“授权但未证实有序” + 负结论进 P9 清单。
- 判断器不判“有没有用”“人分不分得出”，交回盲选和 JND。

## 六、仍未解决（诚实列账）

- **P2 预算阈值**：封顶次数、触发信号 N 未定 → 偏好探针不能开放多人测。
- **P4 stopping rule**：拍脑袋，未接阶梯法/dueling bandits。
- **P5 单评审人**：依赖 P2/P4 先清，顺序反了假清。
- **P7 习惯化漂移**：复审周期无数，1 年有效期缺依据。
- **P8 coverage**：空占位，次数≠覆盖度。
- **P9 未探维度**：信息密度、版式细部、字号阶全程锁定未扰动。
- **P10 情境指纹 schema**：字段来源、禁问偏好不禁问情境的操作边界未标准化。
- **chip 归因是自我报告**，证据等级应低于盲选，结论应是“弱先验+待观察”，不直接路由。
- **环境维度未纳入探测域**：env_fp 重置机制没跑过，漂移会静默污染凭证。

## 七、落地顺序

1. **定变量命名规范**（结构化 + 变量→轴映射表）。
2. **AST 锁验证跑通**：变更集提取 → 映射 → 判单轴/串维/无法映射。
3. **一个轴跑通序性全链**（建议饱和度 / R4 蓝饱和度）：AST 抽值 → 渲染交叉验证 → 单调 → JND。
4. **三态判定器 + R1–R5 回归用例**。
5. **功能/环境实测先行**（宿主加载、工具执行、页面目检、env_fp 重置），自己跑，属 smoke test。
6. **偏好探测暂不开放多人**，等 P2/P4 定稿；那时找人测归因可信度与 JND 标定。

## 八、一句话收口

**代理判“是不是轴”，用户授权判“这个项目值不值得花预算探”——授权是项目级情境层，既不等于偏好，也不判定轴成立或合适。** AST 验锁不验序；严格 1:1 且序性过 JND 才发“绝对轴”，其余分“绝对非轴”与“不确定”；插值只对已证轴开放，授权只开频谱采样。这套口径不追求判定所有轴，只发能被推翻的确定结论——正是协议第 0 条的原意。

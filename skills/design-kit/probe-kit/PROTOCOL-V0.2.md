# 协议 V0.2：代理、授权与判定边界

这份文档是对《设计探针：决策总结》的评审收敛结果，也记录本次在源文件里实际落了什么、什么故意没做。它不替代 `SPEC.md`（协议条款）与 `SHORTLIST-SPEC.md`（粗选），只回答一个问题：

**证据链的每一环，哪些是「已证」，哪些只是「可推翻的代理」，以及为什么现在不继续加层。**

原始建议归档：[`REVIEW-SUGGESTIONS.md`](REVIEW-SUGGESTIONS.md)。逐条采纳情况（采纳 / 部分 / 暂缓 / 未解决）见根 README 的「协议修改建议与采纳情况」一节。

## 0. 结论

1. **P1 不能被证明，只能被代理约束。** 「这个变量对应一个感知维度」是事实主张，任何源码层代理都只能证明「源码里只变了一个变量」，证明不了「这一个变量恰好是一个感知维度」。诚实口径是：**代理 + 可推翻边界 + 回归复现**，而不是「轴纯度已验证」。
2. **架构要二选一：A 模板填充，B 自由生成。** 当前是 A（固定 fixture + 单一占位符 + 值→页面重渲染绑定）。A 模式下不需要 AST；只有走 B（skill 直接产页面）才需要「变了什么」的反推。**本次不启动 AST。**
3. **用户授权是项目级情境层**：它只回答「这个项目值不值得花采样预算探这个维度」，不回答偏好、不判定轴成立、不判定轴合适。授权只发 `spectrum_only` 凭证、不开放插值。
4. **chip 归因保留路由，但必须加事实核查与置信档。** 能力缺口可以核对「候选里到底有没有该能力特征」；核对不上的归因只作弱先验，不直接换工具。

## 1. 现状：哪些环已有事实层

| 环节 | 现状 | 性质 |
|---|---|---|
| 值 → 页面绑定 | `verify` 用 manifest 的 `input.values` + seed 重放，并按值重新渲染 HTML 比对 | 事实（可回归） |
| 页面防篡改 | `run.html`/页面重渲染、页面 `pageSha`、收口产物重算 | 事实（可回归） |
| 盲性 | 可见文本 / 属性 / 百分数 / 小数扫描 | 事实（可回归） |
| **轴纯度** | **本次新增：颜色轴副作用代理**（色相/明度/对比度/色度单调） | 代理（可推翻） |
| 序性 | 值序 + 指认 + 翻转速/置信度/同向性 + JND | 弱证据（n 小） |
| 可辨识阈值 | 轴声明 `jnd`；低于 JND 视为同一档；`apply` 写等效区间 | 已实测（单场景） |

结论：不是「每一环都停在声明上」。缺的是轴纯度这一环，本次用**副作用度量**补，而不是 AST。

## 2. 本次落地（源文件）

### 2.1 轴副作用代理：`lib/side-effects.mjs`

对颜色轴（r4 蓝饱和度）计算：

- 每个变体的 Oklch 色相 / 明度 / 色度、sRGB、相对亮度、与模板底色的 WCAG 对比度；
- 变体之间的色相漂移、明度漂移、对比度漂移、色度单调性；
- 阈值：色相 > 2°、明度 > 0.5 个百分点、对比度 > 0.15、色度不单调 → 判**串维**。

接线：

- `probe.mjs build`：串维直接拒绝生成（不是警告）；
- `manifest.sideEffects` 落盘；落账事件 `run.recorded.sideEffects` 同步携带；
- `probe.mjs verify`：从 `input.values` + 模板重算副作用，与清单比对（防篡改），并把「轴副作用在界内」列为检查项；
- `probe.mjs review`：打印「色相Δ / 明度Δ / 对比度Δ」与结论。

真实数据校验：R4 三轮取值（39.06% / 40.63% / 42.19%）色相Δ = 0°、明度Δ = 0、对比度Δ ≈ 0.004，通过；合成一个「值越大越亮」的轴会被拒绝并报「明度漂移」。

### 2.1b 声明位代理：字号 / 间距轴

模板模式下占位符只出现一次，所以「其它属性会不会跟着变」在源码层可控；真正无法自动证明的是感知耦合。新增两条轴：

- **r5 正文基准字号**（`fixtures/r5/base.html`，占位符 `{{FONT_SIZE}}`，范围 14–20px，JND 暂估 1px）：检查占位符是否落在 `--reader-size` 声明上；已知耦合登记为「行宽/折行会变」「标题固定 px，层级比例会变」。
- **r6 页面纵向节奏**（`fixtures/r6/base.html`，占位符 `{{STACK_GAP}}`，范围 10–40px，JND 暂估 6px）：第一次用 12/18/24px（6px 步长）时评审人看不出差异，因此把 JND 从 2px 上调到 6px，并让同一个节奏变量同时作用于页头留白、卡片内边距、分组间距与页脚（声明为已知耦合，轴上界扩到 40px）；demo 改为 12/24/36px（2×JND）。「看不出」是分辨率证据，不写偏好结论。

插值闸门修正（r6 第二次观察暴露）：`build --between` 原先只要求区间宽 ≥ 2×JND，但插值会生成 3 个内部点、相邻点只差宽/4，端点可辨不代表中间点可辨。现改为**区间宽 ≥ 4×JND**，否则拒绝细分（`--force` 可强制，结论按弱证据处理）。

`analyzeDeclarationSideEffects` 输出 `property / expectedProperty / invariants / knownCouplings / violations`；`build` 拒绝声明位不符的轴，`verify` 重算防篡改，`review` 打印声明位与已知耦合。这是「源码层没串维」的代理，不是感知层证明。

### 2.1c 凭证三态（只读展示）

`credentialState` 新增 `kind` 与 `kindReason`：

- `axis`：副作用在界内 + 收敛 evidence —— 唯一可作插值依据；
- `exploration`：副作用在界内，但收敛未成立 —— 只有频谱/探索证据；
- `unverified`：没有副作用记录或代理未通过。

`review` 每个维度打印凭证类型，`apply` 按类型告警。**暂不阻断 apply**，等 smoke test 与 P2/P4 定稿后再开闸。

### 2.1d Smoke test：`test/smoke.mjs`

11 项仪器通电检查：Node 版本与环境指纹稳定性、三条轴 build+verify、完整链路（build→指认→落账→三态凭证）、env_fp 漂移与复位、页面结构（无外链/占位符干净/run-data 可解析）、插件包结构。脚本末尾列出必须人工/真实环境完成的项目（浏览器目检、真实 DSH 加载、工具子进程、真人 JND 标定），不假装自动完成。

### 2.2 能力归因的事实核查：`lib/shortlist.mjs`

- `analyzeCapabilityEvidence({ htmls, reasonIds })`：只核查**实际用到的能力理由**；扫描候选 HTML 里 image / motion / data / threeD 特征是否存在。
- 语义：用户说「缺素材」，但候选里出现过 `<img>`/`<picture>`/`<figure>`/`background-image:url(...)` → 该理由不被支持；所有用到理由对应的特征都完全缺失 → `supported`（≥75%）。
- `capability-gap.json` 新增 `evidence` 与 `attributionConfidence`；`verify` 从候选页面重算 evidence，与落盘记录比对。
- 归因路由保留，但 capability 路由现在带「支持 / 弱」两档；弱档只作建议，不自动换工具。

注意：`<svg>` 单独出现**不算**真实素材（矢量装饰不是照片/插画）；这是刻意收窄，避免把图标误判成素材。

### 2.3 真实运行回归夹具

- `test/fixtures/real-runs/`：R1–R3 的真实 run 事件切片、R2/R3 的 manifest 与 answer、真实 calibration；
- `test/regression.test.mjs`（10 项）：冻结已知结论——R2=0.4375、R3=0.421875、R1 区间 [0.25,0.5]、收敛 `evidence` + n=3、校准 42% + JND 等效带、真实取值过副作用阈值、串维代理能拒绝、真实回合 verify 仍通过。

「有回归用例才有资格当证据层」这条从现在开始执行：任何改动都要先跑这组夹具。

## 3. 明确暂缓（附理由）

| 项 | 为什么现在不做 |
|---|---|
| AST 变更集 | 当前是 A 模板填充，值→页面绑定已经由重渲染覆盖；AST 只证明「源码只变一个变量」，不证明感知维度。若启动 B 自由生成，先做**声明集 diff**（`:root` 自定义属性 + 使用点扫描），不背完整 CSS/HTML 解析的债。 |
| 默认阻断 apply | 已实现 `--strict` 门槛（只有 axis 凭证可写校准值）；**默认不阻断**是有意的：早期 exploration 样本仍需要落盘成弱默认值，强制阻断会让单评审人的第一轮直接死锁。是否把 strict 设为默认，等真实项目用一段时间再定。 |
| 用户授权字段 | 已实现最小形态：`context.authorization = { question, scope: "spectrum_only", grantedBy }`，只开频谱采样、不开放插值，`review` 展示。尚未做「按轴授权」「授权预算分配」——那需要 P2 预算阈值先定稿。 |
| chip 直接路由的完全降级 | 产品前提是「12 个用尽后判断下一步」。保留路由，但 capability 必须过证据核查；brief / taste / no-preference 继续以「建议」措辞出现，不写成事实。 |
| 环境维度 reset（env_fp） | 已在 smoke 里做「漂移→expired / 复位→恢复」的演练；是否需要更细的重置机制，等真实宿主加载后再看。 |

## 4. 判定口径（写死）

- **能当证据**：真实运行夹具复现 + verify 全部通过 + 轴副作用在阈值内 + 差异过 JND。
- **只能当弱先验**：单评审人指认、chip 自我报告、n < 3、未过 JND 的同向变化。
- **不能当证据**：源码代理单独成立（必须配序性/盲选）、被拒绝的串维变体、没有回归复现的结论。
- 任何代理失败都写进台账，不静默重试。

## 6. 一句话

代理判「是不是轴」，授权判「这个项目值不值得探」，盲选与 JND 判「人分不分得出」——三者不互相替代。本次补的是第一条的最小可用代理（颜色轴副作用）与第二条的证据核查（候选页面事实），并把真实结论冻成回归夹具；AST 与自由生成留到真正需要时再开。

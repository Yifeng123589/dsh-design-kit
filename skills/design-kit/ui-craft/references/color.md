# 色彩策略

何时读我：你在第 2 步定系统、要选配色、要改明暗，或审阅时发现颜色「能用但没观点」时读这一页。先读 [world.md](world.md) 确认为什么长成这样；字体里的颜色层级见 [type.md](type.md)；落地成 token 见 [design-system.md](design-system.md)。

## 1. 先定策略，再定颜色

四种策略，按访客要完成的事选。策略决定颜色的面积与纪律，具体色相轮到 OKLCH 再定。

| 策略 | 定义 | 面积 | 适用模式 | 具体界面 |
|---|---|---|---|---|
| 克制 Restrained | 中性色带一点世界色相，一个强调色只给动作 | 强调色不超过 5% | 操作、阅读 | 排班后台：灰底带 0.01 彩度的冷青，主按钮与选中行用同一深青 |
| 承诺 Committed | 一个饱和色承担大块区域 | 30% 至 60% | 说服、体验 | 招聘官网：赭橙铺满页头色带与首屏右侧色块，主按钮同色 |
| 全彩 Full palette | 3 到 4 个命名角色，每个都有工作 | 每个角色面积稳定 | 阅读、操作、数据密集 | 数据周刊：纸白、墨黑、标注红、链接蓝，加 6 级中性阶 |
| 浸染 Drenched | 页面即颜色，颜色就是环境 | 超过 70% | 说服、体验 | 气候数据站：整页深松绿，白字，图表只用同色相的明暗阶 |

- 先写下策略名再动手。写不出来就是还没决定：默认选克制，只在说服或体验型页面升到承诺。
- 模式决定上限：操作与阅读型最多到全彩，不用浸染；说服与体验型可以从克制直接跳到承诺。
- 色相从世界推导，不按行业套。医疗默认蓝、金融默认深绿、AI 默认紫，都是模板记忆。先问这个产品的材料与场所。

## 2. 明暗不是默认

写一句物理场景再决定：谁、在哪、什么光、看多久。写不出这句话就用亮色，亮色是 web 的默认阅读环境。

| 场景 | 判断 |
|---|---|
| 财务分析师在办公室双屏前，白天开顶灯，连续核对报表 3 小时 | 亮色，降低对比锐度，靠中性阶拉开层级 |
| 运维值班员在夜间值班室，环境灯关闭，看大屏告警 | 暗色，避免整屏白光，告警红降饱和 |
| 外卖骑手在正午户外看手机，屏幕反光 | 亮色高对比，字号加大，不用浅灰字 |

- 暗色不是「高级」的同义词，也不是产品的默认皮肤。按场景写理由，写进 DESIGN.md。
- 同一产品可以有双主题，但默认主题必须由场景决定，不能交给系统偏好随机决定第一印象。

## 3. 用 OKLCH 工作

`oklch(L C H)` 三个分量的直觉：

- `L` 明度 0 到 1：0 是黑，1 是白，0.5 附近是感知中灰。层级主要靠它，不靠加灰。
- `C` 彩度 0 到 0.37：0 是灰，0.03 是几乎察觉不到的底色调，0.12 到 0.2 是界面强调色的常用区，再往上只在大面积展示里用，且容易超出 sRGB 色域。
- `H` 色相 0 到 360：0 到 40 红与粉，40 到 90 橙与琥珀，90 到 140 黄绿，140 到 180 绿，180 到 220 青，220 到 280 蓝，280 到 330 紫，330 到 360 品红。

生成规则：

1. 中性阶共用同一个 H，C 不超过 0.02，只动 L：0.98 背景、0.95 表面、0.9 边界、0.46 次级文字、0.22 正文。
2. 强调色定 hover 与 active 两档：hover 在 L 上 +0.04，active 在 L 上 -0.08，C 基本不动，不换色相。
3. 彩色底上的次级文字用同色相提亮或压暗，不要加灰：`oklch(from var(--accent) calc(l + 0.18) c h)`。
4. 边界色半透明，跟随表面：`color-mix(in oklab, var(--text) 12%, transparent)`。正文与按钮文字不用半透明色，对比度会随背景漂。
5. 明度靠近两端时降低彩度。白底附近的浅色与黑底附近的深色都别保留高 C，否则颜色显脏。
6. OKLCH 只负责生成与调整。对比度用 WCAG 相对亮度验证，两把尺子不同，不要拿 L 差估算比例。

```css
:root {
  --bg: oklch(0.98 0.006 210);
  --surface: oklch(0.95 0.008 210);
  --text: oklch(0.22 0.012 210);
  --text-muted: oklch(0.46 0.012 210);
  --border: color-mix(in oklab, var(--text) 12%, transparent);
  --accent: oklch(0.48 0.13 210);          /* 白字对比度 5:1 以上 */
  --accent-hover: oklch(0.52 0.13 210);
  --accent-active: oklch(0.40 0.12 210);
  --accent-contrast: oklch(0.99 0.01 210);
}
```

## 4. 对比度

| 内容 | AA 下限 |
|---|---|
| 正文、占位符、次级文字 | 4.5:1 |
| 大字（24px 以上，或 19px 以上粗体） | 3:1 |
| 图标、表单边界、焦点环 | 3:1 |

WCAG 公式的直觉：`对比度 = (亮者 + 0.05) / (暗者 + 0.05)`。亮暗是线性化后的相对亮度，绿权重最大，蓝最小；0.05 是给纯黑的补偿，所以黑白是 21:1，不是无穷大。

- 不要靠看。跑 `node scripts/design-tokens.mjs` 生成后读它的对比度自检输出，或看浏览器 DevTools 的对比度读数。
- 半透明叠层、图片上的文字、禁用态、两套主题都要按最终合成色计算。彩色底上配灰色次级文字是最高频的失败。
- 大字的 24px 按实际渲染字号算，`clamp()` 在移动端算出的值也要过一遍。
- 信息不能只靠颜色编码。状态、数据序列、必填项都要同时有文字、图标或形状。

## 5. 状态色

- 状态色与品牌强调色分开。成功用 145 至 155 的绿，警告用 75 至 85 的琥珀，危险用 25 至 35 的红，信息用 240 至 250 的蓝。
- 品牌色占了某个状态色相时，换色相，或者改由图标与文字承担区分，不要让同一个颜色既表示品牌又表示成功。
- 常见错误一：品牌绿直接当成功色。用户分不清品牌与成功，界面一出现品牌色就以为操作成功。
- 常见错误二：纯红 `#FF0000`。饱和度顶格，白底上刺眼、暗底上振动，用 `oklch(0.55 0.18 30)` 这一档。
- 警告黄不能当白底上的文字色，对比度不够。黄做底，配深色文字。
- 只靠颜色区分状态不合规。图标、文案、形状至少再变一项，色盲用户才能分辨。

## 6. 暗色模式

暗色不是把亮色反相，是重新定 L 与 C。

- 不用纯黑 `#000` 与纯白 `#FFF`。背景用 `oklch(0.16 0.008 H)` 一档，正文用 `oklch(0.93 0.01 H)`，避免长时间阅读的光晕与眩光。
- 表面分 3 到 4 级 elevation：背景 0.16、表面 0.19、浮层 0.22、模态 0.26，越靠前越亮。明度差 0.03 已足够分辨。
- 暗色下彩度降 15% 至 25%，大面积品牌色尤其要降，否则在暗环境里发光、刺眼。
- 阴影在暗底几乎不可见，改用 1px 边界与表面明度差表达层级；只在真正的浮层上保留阴影。
- 亮色的强调色搬到暗色通常要提 0.15 左右的 L，尤其当它承担文字色与图标色时；每个语义色分别验证，按钮文字的对比度按最终底色算。
- 两套主题同时支持：`@media (prefers-color-scheme: dark)` 与 `[data-theme="dark"]`。根上写 `color-scheme: light dark`，滚动条与表单控件跟着变。

```css
:root { color-scheme: light dark; }
@media (prefers-color-scheme: dark) {
  :root {
    --bg: oklch(0.16 0.008 210);
    --surface: oklch(0.19 0.009 210);
    --surface-raised: oklch(0.22 0.01 210);
    --text: oklch(0.93 0.01 210);
    --text-muted: oklch(0.68 0.012 210);
    --border: color-mix(in oklab, var(--text) 16%, transparent);
    --accent: oklch(0.68 0.12 210);
    --accent-contrast: oklch(0.14 0.01 210);  /* 暗底上按钮改深色文字 */
  }
}
```

## 7. 禁止的默认色

| 反例 | 为什么 | 换成 |
|---|---|---|
| `linear-gradient(135deg, #6366F1, #8B5CF6)` 当主视觉 | AI 紫渐变是 2018 年以后 SaaS 模板的默认皮肤，出现即被读成模板 | 定一个色相，让它承担整块区域（见第 8 节） |
| 彩虹渐变文字 `background-clip: text` | 对比度算不出来，小字不可读，打印丢失 | 一种颜色加字重与字号做强调 |
| 没有信息功能的玻璃拟态 `backdrop-filter: blur(20px)` | 边界对比不足，性能开销大，内容可读性下降 | 不透明表面加 1px 边界 |
| 品牌色铺满整页且无留白 | 没有层级，没有呼吸，压迫大于主张 | 颜色分给区域，留白留给内容 |
| 每张卡片一个色相、图标全彩 | 颜色不携带意义，只剩撒点 | 一个强调色，其余走中性阶 |
| 每个区块都放装饰性渐变光晕 | 「不知道放什么就加光」的产物，删掉页面不会变差 | 删掉，用留白与栅格组织 |

- 装饰性渐变、光晕、彩色描边都不是颜色策略。颜色要绑定区域、动作或状态，绑定不了就删。
- 渐变本身不禁止：需要模拟材质、光影或数据区间时可以用，但要在渲染结果里能说出它代表什么。

## 8. 色彩在页面尺度

颜色按区域分配，不是在中性底上撒彩点。

一个强调色的三种用法：

1. **区域**：首屏或一个 section 用强调色的浅阶铺满 30% 至 60% 面积，承载论点。例：`oklch(0.94 0.04 H)` 铺底，配 `oklch(0.22 0.02 H)` 文字。
2. **动作**：主按钮、焦点环、选中态共用同一强调色，全页唯一，面积不超过 5%。次按钮用描边，不给第二个填充色。
3. **标记**：图表主序列、关键数字、引用线用同一色相的深阶。数据序列靠明度或形状区分，不引入第四个色相。

- 每增加一个色相，回答它承担什么角色。答不上来就不加。
- 页面 60% 是中性色，30% 承载内容，颜色分给剩下 10%；或者整块区域就是颜色。两种都是策略，中间地带那种「到处点一点强调色」最难看。
- 与模式配合：操作型强调色稀有，说服型可以让颜色占主导。同一产品里不同页面允许不同面积，但语义色（成功、危险、焦点）全局一致。
- 落地为 token 时只暴露语义名，不暴露 HEX：`--accent`、`--danger`、`--focus`，具体值见 [design-system.md](design-system.md)。

## 交付前检查

- [ ] 先写了策略名（克制、承诺、全彩、浸染）和一句物理场景，颜色不是凭手感选的。
- [ ] 中性阶与强调色都在 OKLCH 里定义，hover 与 active 只动 L，不换色相。
- [ ] 正文 4.5:1、大字 3:1、图标与焦点环 3:1 全部实测通过，包括两套主题。
- [ ] 状态色与品牌强调色可区分，没有用纯红，也没有只靠颜色传达状态。
- [ ] 暗色主题单独调过 L 与 C，没有纯黑纯白，表面有 3 到 4 级 elevation。
- [ ] 页面里没有 AI 紫渐变、彩虹文字、无意义玻璃、满屏品牌色。

# 中文 UX 文案

何时读我：写按钮、标题、错误、空状态、加载与确认提示，或要把英文营销文案改写成中文时读这一页。语气要服从方向和模式，先读 [world.md](world.md) 与 [modes.md](modes.md)；文案在界面里的状态呈现见 [states.md](states.md)。

## 1. 按钮：动词开头，说清结果

- 按钮文字 = 动词 + 对象或结果。能写「保存并发布」就不要写「确定」。
- 「提交」「确认」「确定」不单独出现。补上发生什么：「提交审核」「确认删除」「保存修改」。
- 危险操作写明对象与数量：「删除 3 个文件」「移除成员」。确认弹窗里的按钮同样写全，不写「是」「否」「OK」。
- 能撤销就不用确认弹窗。需要确认时正文说后果：「删除后 30 天内可在回收站恢复」。
- 同一概念全站用同一个动词。不要在 A 页叫「导出」、B 页叫「下载」、C 页叫「保存到本地」。

| 反例 | 正例 |
|---|---|
| 确定 | 保存并发布 |
| 提交 | 提交审核 |
| 取消 | 放弃修改 |
| 删除 | 删除 3 个文件 |
| 了解更多 | 查看定价与功能对比 |

## 2. 标题与副标题

- 标题回答三件事之一：这是什么、给谁用、有何不同。副标题补证据或范围：数量、来源、时间、适用对象。
- 判断标题合不合格：把品牌名换成竞品名，句子还成立，说明它没有说自己。
- 标题不堆形容词。把「智能、高效、专业」换成一个可验证的事实。

| 英文营销腔 | 中文具体说法 |
|---|---|
| Redefine the future of work | 把排班、交接和请假放进一个日历 |
| Everything, simplified | 报销从 8 步减到 3 步，票据拍照即填 |
| Empower your team to do their best work | 每个人都能看到自己本周的 5 项任务和截止时间 |
| Next-generation collaboration platform | 支持 200 人同时编辑同一份文档 |
| Built for the future of work | 远程团队按城市时区自动排会议 |

## 3. 错误信息

一条可用的错误回答三件事：发生了什么、为什么（知道的话）、下一步怎么做。第一句就是结论。

- 不甩锅。「你输入的内容有误」改成「邮箱缺少 @ 符号，形如 name@company.com」。
- 校验错误指向字段与规则，提示放在字段旁边；表单顶部再放一条摘要，两处都有。
- 网络错误给重试，并说清影响：「网络断开，刚才的修改没有保存。检查连接后重试。」
- 内部错误码放次要位置，不放进第一句。不承诺系统不知道的原因和恢复时间。
- 不用惊叹号，不写「糟糕」，不拿事故开玩笑。

| 反例 | 正例 |
|---|---|
| 错误：500 | 保存失败，服务器暂时没有响应。草稿已保留，30 秒后重试或手动复制。 |
| 密码格式不正确 | 密码至少 8 位，需包含一个数字。 |
| 文件上传失败 | 文件超过 10MB，压缩后重新上传。 |
| 网络异常 | 连接已断开，修改还在本地。恢复网络后点「重新保存」。 |

## 4. 空状态

空状态不是装饰位。说清三件事：这里会出现什么、第一条内容怎么来、现在点哪里。

- 反例：一张灰色插画加「暂无数据」。
- 正例：「还没有发票。上传第一张发票，系统会自动识别金额与税号。」主按钮「上传发票」。
- 区分四种空：首次使用、筛选无结果（给清除筛选）、无权限（说明找谁开通）、加载失败（给重试）。四种文案不能共用一句。
- 空状态里不放大段说明。一个标题、一句原因、一个主行动，最多再加一个次要链接。

## 5. 加载与成功

- 超过 1 秒给进度感。能算进度就写「正在上传 3/8」，算不出来就写真实操作名「正在校验文件」，不写「加载中」这种没有信息量的文案。
- 不造假进度条。时长不确定就用循环指示器，再加一句操作说明。
- 成功反馈说清结果与下一步，能省就省：「已发布，链接已复制」比「操作成功」多两个有用信息。
- 常规成功用轻提示，3 秒自动消失；需要用户确认后果的操作（付款、发布、删除）才用常驻提示。
- 加载失败要给重试，并且明确丢没丢数据：「上传失败，文件还在本地，可以重新上传」。

## 6. 语气与称呼

- 称呼二选一，全站统一。默认用「你」，适合现代 web 产品、社区与工具；企业采购、金融、政务、医疗签署类界面用「您」。选定后写进 DESIGN.md，不再改。
- 术语一致：同一个对象只有一个名字。先列一张小词表，再写页面，避免「项目、工程、任务」混用。
- 句式用中文短句，一句说一件事，避免把条件、时间、对象全塞进一个长定语从句。把「在您提交的申请经过审核并通过之后我们将通知您」拆成「审核通过后，我们会通知你」。
- 不用文学修辞、双关、谐音。界面文案服务的是正在完成任务的人，不是读者。

## 7. 数字、日期与单位

- 数字与中文、英文之间留一个半角空格：删除 3 个文件、等 5 分钟、5 kg、12 px。
- 千分位用半角逗号，四位数以上才加：12,480。年份不加：2026。
- 百分比紧贴数字：60%。百分比区间用「至」：12% 至 18%。
- 货币符号紧贴数字：¥99、¥99.00；范围 ¥99 至 ¥299。中文单位另写空格：99 元。不混写「¥99元」。
- 日期写 2026 年 11 月 2 日；表格与系统时间可用 2026-11-02。不写 11/2 这种有歧义的格式。
- 时间区间用「至」：09:00 至 18:00，不用波浪号。跨时区标注：09:00（UTC+8）。
- 数量与量词完整：写「共 3 位成员」，不用「们」表示复数，不写「1 个用户们」。

## 8. 中英混排

- 中文与英文之间留一个半角空格：「用 Figma 打开」「第 3 步」。全角标点前后不重复加空格。
- 产品名与专有名词按官方大小写：GitHub、iPhone、macOS、JavaScript。
- 代码、文件名、路径、快捷键用等宽或 `<code>` 标出，避免与正文混淆。
- 英文缩写首次出现给中文全称，之后只用缩写：「内容安全策略（CSP）」。不在中文句子里生造英文动词。

## 9. 黑名单

营销腔，换成具体事实或直接删：重新定义、未来已来、让一切更简单、一站式、闭环、生态、抓手、拉通、对齐、沉淀、颗粒度、组合拳、降本增效、沉浸式、革命性、无限可能、开启新篇章。

翻译腔，改成中文说法：让我们一起、点击这里、请知悉、您的反馈对我们很重要、欢迎来到、即刻、解锁、探索更多、开启旅程、我们相信、更多精彩。

| 反例 | 正例 |
|---|---|
| 重新定义团队协作 | 把会议记录、任务和文件放进同一个项目 |
| 让一切更简单 | 三步完成报销，不用再填纸质单 |
| 一站式解决方案，构建高效闭环 | 排班、请假、交接在同一个页面完成 |
| 您的反馈对我们很重要 | 反馈会由产品团队在 2 个工作日内回复 |
| 点击这里了解更多 | 查看定价与功能对比 |

- 黑名单不是一步到位：先写完，再逐句问「这句话删掉后用户会不会少知道一件事」，不会就删。
- 数字与专有名词是可信度的来源，保留具体数字、来源与生效日期，比任何形容词都有说服力。

## 交付前检查

- [ ] 每个按钮都以动词开头，能说出点击后发生什么；没有单独的「提交」「确认」「确定」。
- [ ] 危险操作的按钮写明了对象与数量，确认弹窗里的按钮不是「是」「否」。
- [ ] 标题去掉品牌名后仍有信息；没有一个标题只由形容词和行业名词组成。
- [ ] 错误信息包含发生了什么、下一步怎么做，网络错误给了重试，校验错误指向字段。
- [ ] 空状态说明了会出现什么、第一条怎么来、点哪里；不是灰插画加「暂无数据」。
- [ ] 称呼全站统一，同一个对象只有一个名字，数字、日期、单位符合第 7 节的写法。

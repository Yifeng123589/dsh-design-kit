# 产品界面

何时读我：做后台、仪表盘、编辑器、设置页、数据表格、对话/流式界面、命令面板这类「用」的界面，而不是「看」的页面。操作模式（Operate）的主要战场。

产品界面的审美标准和营销页相反：**少一点表达，多一点确定。** 用户来这里是为了完成任务，不是来看设计。品牌感藏在精确的细节里：对齐、密度、状态、键盘路径。

## 1. 密度是设计变量

营销页的留白是呼吸，产品界面的留白是效率损失。先定密度档位，再谈间距：

| 档位 | 行高 | 适用 |
|---|---|---|
| 紧凑 | 32-36px | 数据表格、日志、文件列表、开发者工具 |
| 标准 | 40-44px | 表单、列表、导航、设置项 |
| 宽松 | 48-56px | 面向非专业用户、移动端、触屏优先 |

同一个界面里可以有两档（例如表格紧凑、表单标准），但不能有三档以上。密度由使用频率与信息量决定：一天用 50 次的界面要紧凑，一周用 1 次的可以宽松。

**反例：** 后台每个设置项占 80px 高、一屏只放 4 项，用户要滚 6 屏才能改完密码。

## 2. 数据表格

表格是产品界面里最容易做坏、也最值得做好的组件。

必须有的：

- 数字右对齐、等宽数位（`font-variant-numeric: tabular-nums`），文字左对齐。
- 表头与内容对齐方式一致；表头可排序时给出方向指示。
- 行悬停高亮，选中态与悬停态可区分。
- 空结果、加载、错误三种状态，不要让表体变成空白。
- 长文本截断给 `title` 或详情入口，不要硬撑破列宽。
- 分页或虚拟滚动，超过 100 行必须做。
- 列宽用内容驱动，不要等分。

**反例：** 8 列表格每列等宽，金额居中，长描述把行撑成三行高，鼠标移上去没有反馈。

## 3. 流式与部分结果

对话、生成、同步这类界面，内容会一段段出现。设计要回答三个问题：

1. **正在发生什么：** 明确的状态词（「正在读取文件」而不是一个转圈）。
2. **已经有什么：** 已到达的内容立即可见、可复制、可中断。
3. **如何停下来：** 提供停止/取消，且停止后保留已有结果。

规则：

- 文本流式输出时保持滚动锚定在底部，用户手动上滚后停止自动跟随。
- 不要把已显示内容重新排版（跳字、跳行），增量追加。
- 工具调用、思考过程这类中间态，默认折叠，展开可见，不要占据主视觉。
- 失败时保留已生成部分，给出重试，不整段丢弃。

**反例：** 生成时整屏显示骨架屏，完成后一次性弹出全部内容；用户无法中途停止。

## 4. 设置与表单页

- 分组：按「用户的心智模型」分组，不按数据库字段。一组 3-7 项。
- 每项给默认值，不给空输入框让用户猜。
- 危险操作隔离到单独区域，写清后果与影响范围，二次确认要具体（输入名称确认，而不是「确定吗」）。
- 保存策略明确：自动保存要给「已保存」反馈，手动保存要有未保存提示与离开拦截。
- 即时生效 vs 保存后生效必须在界面上区分。
- 搜索：设置项超过 30 个就该有搜索。

## 5. 命令面板与键盘路径

有键盘路径的产品界面，专业用户会记住它。

- `Cmd/Ctrl + K` 打开命令面板，支持模糊搜索、箭头选择、回车执行、Esc 关闭。
- 全局快捷键不与浏览器冲突；能被发现（菜单里标注快捷键）。
- Tab 顺序与视觉顺序一致；焦点环自定义但必须可见。
- 浮层打开时焦点进入浮层，关闭后回到触发元素；Esc 可关闭。
- 提供跳过导航的链接（skip link）。

**反例：** 命令面板只能鼠标点，Esc 关不掉，打开后焦点还在后面的页面上。

## 6. 通知与反馈

- 操作反馈就近出现（按钮变成「已复制」），不要全屏 toast。
- Toast 不承载必须阅读的信息；错误要留在原地。
- 破坏性操作可撤销优于二次确认。
- 长任务给进度与预计时间，或至少给「还在运行」的可见证据。
- 不要用颜色作为唯一状态信号，配图标或文字。

## 7. 暗色优先

开发者工具、编辑器、监控这类场景天然暗色。暗色不是反色：

- 表面用 3-4 级 elevation（页面底 → 卡片 → 浮层 → 弹窗），靠明度差与边框区分。
- 避免纯黑 `#000` 与纯白文字 `#FFF`，用 `oklch(12% ...)` 与 `oklch(92% ...)`。
- 暗色下阴影几乎不可见，改用 1px 边框与表面提亮。
- 强调色在暗背景上要降彩度、提明度，否则刺眼。
- 图表配色在暗色下重新校验对比度。

## 8. 空、错、加载

产品界面的三种状态决定用户是否信任这个工具。

- **空：** 说明这里会有什么、为什么现在是空的、给一个主行动。首次空与清空后空分开写。
- **错：** 局部失败不影响整页；错误说清「哪一步失败 + 为什么 + 怎么办」；给重试；保留用户输入。
- **加载：** 100ms 内不显示任何加载态；100ms-1s 用骨架或占位；超过 1s 给进度或分步状态。骨架形状要接近真实内容，不要用统一灰条。

## 9. 数据可视化

- 图表只有在「比较、趋势、分布、关系」四类问题里选一个，不为装饰而画。
- 一图一结论：标题写结论，不写「各月份数据」。
- 坐标轴从 0 开始（除非明确说明截断）；网格线弱化；标签不要旋转 45 度硬塞。
- 颜色不超过 5 个语义色；分类色要能区分色盲用户（不只靠色相）。
- 数据点超过 200 个考虑聚合或采样，并在界面说明。
- 空数据、单点数据、异常值都要有处理。

## 10. 验收

- [ ] 密度档位只有 1-2 档，且与使用频率匹配
- [ ] 表格：数字右对齐等宽、空/错/加载三态、长文本处理
- [ ] 流式界面可中断、可保留、不跳版
- [ ] 设置页按心智模型分组，危险操作隔离并具体确认
- [ ] 键盘路径：Tab 顺序、焦点环、Esc、Cmd/Ctrl+K（如适用）
- [ ] 暗色用表面层级而非反色，图表对比度重新校验
- [ ] 空/错/加载三态文案具体，不是「暂无数据」「出错了」

# 版式与栅格

**何时读我**：方向已定、准备把内容排成页面时读我；如果还在纠结「这个网站该长什么样」，先读 [world.md](world.md)，方向没定，栅格只是在给错误的内容做美化。

## 间距：先把阶梯定死

用 4px 基准，不用 8px。8px 阶梯会漏掉 12px，而 12px 正好是标签与输入框、标题与导语之间最合适的距离，漏掉它你只能被迫用 16px，整页永远松半档。

```css
:root {
  --space-1: 4px;   --space-2: 8px;   --space-3: 12px;
  --space-4: 16px;  --space-5: 24px;  --space-6: 32px;
  --space-7: 48px;  --space-8: 64px;  --space-9: 96px;
  --space-10: 128px;
}
```

只允许用这 10 个值。出现 20px、36px、72px 时，说明你在凭手感排版，把它归到最近的阶梯值。

**同组紧、组间松**：同组元素之间 8-12px，组与组之间 32-48px，两者至少差 3 倍。检验方法：把组内间距翻倍，如果画面仍然分成原来那两组，说明你本来就没有用间距分组。

```css
/* 反例：间距写在每个元素上，谁挨着谁取决于 DOM 顺序 */
.item { margin-bottom: 16px; }
.item--featured { margin-bottom: 32px; }

/* 正例：两层容器各自拥有节奏，子元素不带外边距 */
.block { display: grid; gap: var(--space-6); }  /* 组间 32px */
.group { display: grid; gap: var(--space-3); }  /* 组内 12px */
```

`gap` 比 margin 好在三件事：不会折叠、不用处理最后一个子元素、改一处就改整组。只有需要单边不对称空隙时才写 margin，而且只写一次。

**标题上方大于下方**：标题上方的空属于「上一节的结束」，下方的空属于「标题自己的内容」，上方至少是下方的 1.5 倍，常见做法是 3 倍。

```css
.section {
  display: grid;
  gap: var(--space-3);            /* 标题到正文 12px */
  padding-block: var(--space-8);  /* 节与节之间 64px，上下对称 */
}
```

相邻两节的内边距不折叠，标题上方实际是 128px，下方 12px。

**一节页面的纵向节奏**：

| 位置 | 值 | 说明 |
|---|---|---|
| 首屏底部到下一节 | 96-128px | 全页最大的空 |
| 节与节之间 | 64-96px | 用 padding 或 gap，不用 margin |
| 标题到正文 | 12-16px | 别超过 16，否则标题飘走 |
| 条目与条目 | 8-12px | 同组 |
| 组与组之间 | 32-48px | 至少是组内的 3 倍 |

## 栅格：给阅读宽度，不给装饰

默认 12 列，用于营销页、文章、落地页。数据密集的后台用 16 列，因为 16 能被 2、4、8 整除，表格和卡片模块容易对齐。同一页只用一个列数。

设计稿按 1440 宽画：页面边距 64-96px，gutter 24-32px，内容区最大 1200-1280px，正文栏宽 65-75 个字符（中文 30-40 个字）。移动端按 390 宽画：边距 16-20px，gutter 16px，单列。

```css
.page {
  --gutter: clamp(16px, 2vw, 32px);
  --margin: clamp(16px, 5vw, 96px);
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  column-gap: var(--gutter);
  padding-inline: var(--margin);
  max-width: 1440px;
  margin-inline: auto;
}
.page > .prose { grid-column: 2 / span 6; }  /* 左侧空 1 列，正文不居中 */
.page > .aside { grid-column: 9 / -1; }
```

`minmax(0, 1fr)` 不能省：内容超宽时，等分列会被撑破，页面出现横向滚动。

**两种不要用栅格的情况**：编辑式的不对称构图（主图跨 7 列、文字从第 3 列开始、故意空掉一列）；全出血图像（宁可在栅格之外单独排，也不要被 12 等分拉变形）。

```css
/* 全出血：三列布局，中间是内容轨道，两侧吃掉剩余空间 */
.shell {
  display: grid;
  grid-template-columns: 1fr min(75rem, 100% - 2rem) 1fr;
}
.shell > * { grid-column: 2; }
.shell > .bleed { grid-column: 1 / -1; }
```

不要用 `width: 100vw` 做全出血，有滚动条时它会多出十几像素，横向滚动条就是这么来的。

## 层级：不要只靠字号

四个工具：字号、字重、颜色、留白。相邻两层至少改变其中两个，否则层级在缩略图里会塌掉。字号本身的规则见 [type.md](type.md)。

| 层 | 字号 | 字重 | 颜色 |
|---|---|---|---|
| 页面主张 | clamp(40px, 6vw, 72px) | 600 | 主文字色 |
| 区块标题 | 24-28px | 600 | 主文字色 |
| 正文 | 16-18px | 400 | 主文字色 |
| 次要信息 | 14-15px | 400 | 次级文字色 |
| 元信息 | 12-13px | 400 | 更浅，但对比度仍 ≥4.5:1 |

反例：h1 40px/700，h2 36px/700，正文 16px/400。两个标题只差 4px，缩略图上完全分不开，这是 `type-scale-flat` 的典型形态。正例：h1 64px/600，h2 26px/600，正文 17px/400，次要 15px/400 灰色。

**一屏只有一个第一眼**：最重的元素只能有一个。把页面缩到 20% 看缩略图，问「第一个跳出来的是什么」；如果三个东西同时跳出来，减掉两个，通常先从「删掉装饰色块、加粗、彩色按钮」开始。导航和主行动按钮的重量必须明显低于主标题，否则首屏有两个第一眼。

## 首屏构图：第一屏是一个论点

访客停留 3 秒，只回答两个问题：「这是干什么的」和「和我有什么关系」。logo、导航、页头不是内容，别把第一屏花在它们身上。

| 构图 | 适合 | 做法 | 风险 |
|---|---|---|---|
| 全出血图像 + 单句 | 作品集、体验型页面、有强视觉素材的品牌页 | 图像占满宽、高 70-90dvh，标题压在一侧，用 40-60% 不透明度的遮罩保证对比度 ≥4.5:1 | 图像与业务无关，只剩漂亮 |
| 非对称两栏 | 说服页、定价页、注册页 | 左 7 列放主张与证据，右 5 列放表单或截图，两栏不对齐中线 | 各占一半就退回模板 |
| 超大字号 + 小正文 | 观点强、文字本身就是视觉的内容 | 主张 clamp(48px, 8vw, 96px)，行高 0.95-1.05，字距 -0.02em 到 -0.04em，正文只写 1-2 行 | 中文超大字容易挤，先检查断行 |
| 产品界面演示 | 工具、后台、开发者产品 | 首屏直接露出真实界面：截图、可操作 demo 或一段能复制的代码 | 截图过小、整片灰，等于没放 |

```css
.hero {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  gap: var(--gutter);
  align-items: end;
  min-height: 70dvh;
  padding-block-end: var(--space-9);
}
.hero__claim { grid-column: 1 / span 7; }
.hero__proof { grid-column: 9 / -1; } /* 第 8 列空着，这是不对称的来源 */
```

**自检**：用一个小时后的记忆验证第一屏。让没看过这页的人看 30 秒，关掉，过一小时问他「那页讲了什么」。回答里有观点、数字或产品动作，通过；回答是「有个大标题和一个绿色按钮」，说明第一屏只有装饰没有论点。

## 密度与留白

挤还是空，看三件事：使用场景（快速扫读还是坐下来细读）、阅读距离（桌面 50-70cm，手机 30-40cm）、信息价值（每次都要看的数据，还是一年看一次的品牌文案）。

| 区域 | 默认值 | 理由 |
|---|---|---|
| 后台表格行 | 40-44px 高（触屏 48px） | 高频重复操作，密度优先 |
| 设置表单 | 字段间 24px，组间 48px | 要读提示和错误 |
| 文档正文 | 行高 1.7，段间 16-24px，宽 30-40 汉字 | 长文连续阅读 |
| 落地页 section | 上下 64-96px | 距离远、信息少 |
| 商品与文章列表 | 卡片间 24-32px，卡内 16px | 比较型浏览 |

不要把「空气感」当万能答案。反例：后台每行 80px 高、字 12px 浅灰，一屏只看到 4 条数据，核对 20 条要滚 5 屏，这是拿留白掩盖信息架构问题。反例之二：正文 15px 却给 2.2 的行高，读起来像散架。

留白上下都要给。反例：所有元素都写 `margin-bottom: 24px`，最后一个元素没有下边距，于是每个节的开头都贴着上一节的结尾。用容器 `gap` 或 `padding-block` 就不会有这个 bug。

## 响应式：内容驱动的断点

不要一上来抄 768/1024。从 320px 开始把窗口慢慢拉宽，记下三种失败出现的位置：文字断行难看、元素开始重叠、点击区小于 44px。在这三个位置加断点，通常 3 个就够。默认起点 480 / 720 / 1080，实际以你测出来的为准。

```css
:root {
  --page-margin: clamp(16px, 4vw, 80px);
  --gutter: clamp(16px, 2.5vw, 32px);
}

h1 { font-size: clamp(2rem, 1.1rem + 3.6vw, 4.5rem); line-height: 1.05; }
.wrap { width: min(100% - var(--page-margin) * 2, 1200px); margin-inline: auto; }
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  gap: var(--gutter);
}

@media (min-width: 720px) { .layout { grid-template-columns: 7fr 5fr; } }
@media (pointer: coarse) { .icon-btn { min-width: 44px; min-height: 44px; } }
@media (hover: hover) { .card:hover { border-color: var(--border-strong); } }
```

- 移动优先：基础样式写给 390px，`min-width` 往上加。桌面不是放大版：移动底部导航、桌面左侧栏；移动单列、桌面 7/5；移动整页进入、桌面侧滑抽屉。
- 触屏目标 ≥44×44px，图标按钮用 padding 补足，相邻目标留 8px 防误触。
- 不要给容器写死高度。`height: 420px` 的首屏遇到中文长标题或用户放大字号立刻溢出，用 `min-height` 加 `padding-block`。
- 用 `dvh` 而不是 `vh`：移动浏览器地址栏收起时，`100vh` 会比可见区域高一截。

## 反模式

- **卡片海洋**：每一段都装进同尺寸圆角卡片，连「关于我们」一句话也是卡片。改用不同版式：一句大话、一张全出血图、一段纯文字、一张表格，让节奏有变化。
- **卡片套卡片**：外层有 padding 和阴影，内层也有，等于两层边框套两层留白。内层改用分割线或纯背景色。
- **满屏三种栅格**：12 列营销区、4 列卡片区、2 列图文区同页出现，任何边界都不对齐。全页统一一套列宽和 gutter。
- **居中一切**：所有区块居中、所有文字 `text-align: center`，左对齐的扫读优势全丢。只有短标题和 CTA 可以居中。
- **留白只在下方**：靠 margin-bottom 排版，最后一个元素没边距，节首永远挤。用容器 gap。
- **负 margin 拉间距**：`margin-top: -40px` 把两节叠起来，一改字号就重叠。先问「这两块为什么必须贴在一起」，如果是一组，就放进同一个容器。

## 检查项

- [ ] 间距只用了 10 档阶梯，没有 20px、36px 这类手写值。
- [ ] 同组间距 ≤12px，组间距 ≥32px，中间没有 16-24px 的模糊地带。
- [ ] 每个 section 的标题上方空隙至少是下方的 1.5 倍（常见做法 3 倍）。
- [ ] 缩到 20% 看缩略图，能指出唯一的第一眼元素。
- [ ] 断点来自实测失败位置，不是抄来的 768/1024。
- [ ] 没有固定高度容器、卡片套卡片、一屏三种栅格。

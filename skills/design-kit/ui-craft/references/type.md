# 字体与排版

何时读我：你在定字号阶梯、行高、字重、字距、字体栈，或处理中英混排与中文标点时读这一页。字体性格来自世界，见 [world.md](world.md)；空间节奏见 [layout.md](layout.md)；验收项见 [craft-floor.md](craft-floor.md)。

中文排版的差异不在字号阶梯，而在标点、混排间距与字体回退。阶梯与西文共用一套，第 7 节处理只有中文才会碰到的细节。

## 1. 先立字阶

所有字号只从一张阶梯表里取，不写裸值。默认阶梯以 16px 根字号、桌面 rem 计：

| token | px | rem | 用途 |
|---|---|---|---|
| `--text-xs` | 12 | 0.75 | 法务、角标、时间戳 |
| `--text-sm` | 14 | 0.875 | 表头、说明、元数据 |
| `--text-base` | 16 | 1 | 正文、表单、按钮 |
| `--text-lg` | 18 | 1.125 | 引导段、大正文 |
| `--text-xl` | 21 | 1.3125 | 小节标题 |
| `--text-2xl` | 24 | 1.5 | 区块标题 |
| `--text-3xl` | 30 | 1.875 | 页面标题 |
| `--text-4xl` | 38 | 2.375 | 首屏标题（移动端） |
| `--text-5xl` | 48 | 3 | 展示标题（桌面） |
| `--text-6xl` | 64 | 4 | 超大展示字，首屏只用一个 |

- 正文从 16px 起步。14px 只给次要信息，字号差不足 15% 时不要靠颜色分层。
- 12px 的三条边界：法务条款、图片来源、时间戳与角标。12px 不用于按钮、输入框、正文和完成任务必需的信息；10px 及以下一律不用。
- 相邻两档至少差 15%，读者才看得出是两级。阶梯最多 10 档，新增角色先复用已有档。

展示字用 `clamp()` 流动，不要在断点里手写 font-size：

```css
.display {
  /* 360px 视口 38px，1440px 视口 72px */
  font-size: clamp(2.375rem, 1.667rem + 3.15vw, 4.5rem);
  line-height: 1.05;
}
```

公式是 `clamp(下限, calc(基准 + 斜率 × 100vw), 上限)`，斜率 = `(上限 - 下限) / (最大视口 - 最小视口)`。上下限写 rem，用户放大字号时仍然有效；上限不超过 96px。

## 2. 行高

| 角色 | 行高 | 说明 |
|---|---|---|
| 中文正文 | 1.75 | 16px 正文得到 28px 行距 |
| 西文正文 | 1.6 | 密集操作界面可到 1.5 |
| 中文表格单元格 | 1.5 | 只限单行，不用于段落 |
| 标签、表头 | 1.4 | 小字收紧，按字号倍数写 |
| 标题 | 1.1 至 1.25 | 30px 标题约 33 至 37.5px |
| 展示标题 | 1.05 至 1.15 | 48px 以上从 1.05 起步 |

- 正文行高可用区间：中文 1.7 至 1.8，西文 1.6 至 1.75。表格是默认值，长行与深底取上限。
- 行宽越宽，行高越大：一行超过 40 汉字时提到 1.8，窄到 25 汉字可回 1.7。
- 深底浅字再加 0.05 行高，并考虑把字重提一档，浅色字在深底上显得更细。
- 行高只写在承载文本的元素上，不要写在布局容器上。无单位值会按各自字号重算后继承，容器上的行高会漏给整棵子树。

## 3. 字重

- 分两种情况。用字重完整的中文字体（思源黑体、MiSans、HarmonyOS Sans、PingFang SC）时：400 正文，500 导航与强调，600 标题，700 只给展示标题。用系统字体栈兜底（微软雅黑、旧版苹方）时：实际只有 400 与 700 两档左右，500 与 600 会被浏览器合成加粗，中宫糊成一片。
- 不确定字体有没有这一档时，只写 400 与 700，用字号拉开层级。字体没有的档位不要写。
- 不用 300 以下。低分屏和 Windows 125%、150% 缩放下细体发虚；100 与 200 在任何中文界面里都不用。
- 能用变量字体就用，`font-weight: 200 900` 一段声明覆盖所有档位，避免每档单独加载。
- 层级 = 字号 + 字重 + 间距。一次改动不要三样全变；相邻层级字号要一眼可辨，字重至少差一档。强调不靠颜色堆，把正文里彩色的词改成 600 就够了。

## 4. 字距

| 内容 | letter-spacing | 原因 |
|---|---|---|
| 中文正文与标题 | `0` | 汉字本身等宽，加追踪会把词拆成单字 |
| 西文正文 | `0` | 正文收紧伤可读性 |
| 西文展示标题（38px 以上） | `-0.02em` 至 `-0.04em` | 大字号天然显松 |
| 全大写英文短标签 | `+0.04em` 至 `+0.08em` | 补偿全大写字母过挤 |
| 全大写英文长句 | 不用 | 超过 3 个词就拖慢阅读 |

- 中文标题不要写 `letter-spacing: 0.3em`。那是海报标题偶一用的效果，在界面里读起来像字谜。
- 数字表格与金额不靠字距对齐，用 `font-variant-numeric: tabular-nums`；老字体补 `font-feature-settings: "tnum" 1`。
- lint 的 `tracking-tight` 以 -0.02em 为正文下限；展示字短标题可以越过，长句不行。

## 5. 行宽

- 中文正文每行 30 到 40 个汉字，容器宽度约 28 到 38em，按 1em 约等于一个汉字估算。
- 西文 65 到 75ch。行宽按字符数算，不按容器百分比猜。
- 用 `max-inline-size` 限宽并居中，容器变窄时自动收，不会溢出。

```css
.article p { max-inline-size: 34em; }  /* 约 34 个汉字 */
.article .lead { max-inline-size: 30em; }
.article .en { max-inline-size: 70ch; }
```

- 全宽容器里的正文必须限宽。1440px 下不设限的一行能排到 90 个汉字，读第二行时找不到第一行结尾。
- 字号加大时按比例收窄 `max-inline-size`，让每行汉字数保持稳定。

## 6. 字体栈

系统中文无衬线栈，零下载，作为默认：

```css
--font-sans: system-ui, -apple-system, "PingFang SC", "HarmonyOS Sans SC",
  "MiSans", "Microsoft YaHei", "Source Han Sans SC", "Noto Sans SC",
  "Noto Sans CJK SC", "WenQuanYi Micro Hei", sans-serif;
--font-serif: "Source Han Serif SC", "Noto Serif SC", "Noto Serif CJK SC",
  "Songti SC", "STSong", "SimSun", serif;
```

- 顺序按平台优先级：macOS 与 iOS 命中 PingFang SC，鸿蒙命中 HarmonyOS Sans SC，小米与部分安卓命中 MiSans，Windows 命中 Microsoft YaHei，Linux 落在思源黑体、Noto 或文泉驿。
- 西文族排在中文族前面，浏览器先用它渲染拉丁字符，再把汉字回退给后面的中文字体。英文放在中文字体后面会拿到中文字体里设计较弱的拉丁字形。
- 衬线用于阅读型长文、编辑感标题和需要观点的展示字。宋体在 18px 以下发虚，正文用衬线至少 18px、行高 1.8。思源宋体优先走 Web 字体，Windows 的 SimSun 字形旧、粗体靠合成。
- 字体族总数不超过 3：正文、标题、等宽各一。lint 的 `font-family-overload` 以 3 为线。

### 加载顺序

1. 先拉丁后中文。拉丁子集几十 KB，先到先渲染；中文按 `unicode-range` 分包，浏览器只下载页面用到的区段。
2. 首屏最多 preload 两个文件：正文 400，标题 600 或 700。其余交给正常加载。
3. 一律 `font-display: swap`，并用 `size-adjust` 给回退字体对齐度量，减少 CLS。
4. 中文全量字体动辄 4MB 以上，不能直接上线。按页面实际用字子集化，或先用系统栈。

```css
/* 同一 family 拆两段：拉丁先渲染，中文按需下载 */
@font-face {
  font-family: "Brand Sans";
  src: url("/fonts/latin.woff2") format("woff2");
  font-weight: 400 700;
  font-display: swap;
  unicode-range: U+0020-007F, U+00A0-00FF;
}
@font-face {
  font-family: "Brand Sans";
  src: url("/fonts/cjk.woff2") format("woff2");
  font-weight: 400 700;
  font-display: swap;
  unicode-range: U+3000-303F, U+4E00-9FFF, U+FF00-FFEF;
}
```

### 中西文配对

原则：两族气质同频，只在一处形成性格差；第三族只能是等宽，并且只给数据用。同一层里不要放三种气质。

| 场景 | 西文 | 中文 | 为什么成立 |
|---|---|---|---|
| 编辑阅读 | 人文无衬线：Inter、IBM Plex Sans、system-ui | 标题思源宋体 600，正文系统黑体 400 | 标题有观点，正文好读，分工清楚 |
| 工具操作 | 几何无衬线：Space Grotesk、Poppins，只给标题与数字 | 正文思源黑体或系统黑体 | 几何形承担性格，中文保持中性 |
| 数据仪表盘 | 等宽：JetBrains Mono、IBM Plex Mono，只给数字与代码 | 正文 IBM Plex Sans 加思源黑体 | 数字对齐，正文不抢戏 |

- 配对失败的样子：标题用圆润几何无衬线，正文用宋体，两种气质在同一视线里打架。中文正文换字体对可读性的影响远大于西文标题换字体，预算有限时先保证中文正文的字体质量。
- 不要拿 Arial 或微软雅黑当唯一方案。Arial 只有两档字重，大标题字腔紧、观感廉价，中文回退不可控，常把宋体与雅黑混进同一行；微软雅黑是 Windows 十几年的默认界面字体，用户一看就想到系统对话框，字重只有三档，中文没有 500 与 600。两者可以留在栈尾兜底，首选 PingFang SC、HarmonyOS Sans SC、MiSans、思源黑体这类有设计意图、字重完整的字体。

## 7. CJK 细节

### 7.1 中英混排的间距

- 首选交给浏览器：`text-autospace: normal` 在汉字与拉丁字母、数字之间自动留出约 1/6 em 的间距，`text-spacing-trim: normal` 收紧全角标点两侧的多余空白。不支持这两个属性的浏览器直接忽略，只是没有间距，不破坏布局。
- 需要兜底时在模板里插入薄空格 U+2009，不要用 U+0020。普通空格宽 1/4 em，比排版需要的更宽，而且会被复制、搜索、翻译带走；薄空格只用于纯静态展示文案。
- 不要用 `letter-spacing` 做混排间距，它同时作用于英文单词内部，英文会散开。

### 7.2 标点

- 中文标点用全角：，。；：、（）“”《》。数字、英文、代码用半角。不要混用，也不要用英文句点代替中文句号。
- 标点不重复：「真的吗？」后面不再加第二个问号，问号和感叹号不连用。lint 的 `cjk-double-punct` 抓这一类。
- 省略号用「……」六个点，占两个字宽；不要用三个英文句点，也不要用三个中文句号。
- 破折号只在语义突变处出现一次，界面文案里不用它代替冒号或括号。中文破折号不是两个英文连字符，也不要连续叠三四个。
- 引号用弯引号 “ ” 与 ‘ ’，不用直引号（代码除外）。嵌套引用先双后单。

### 7.3 断行与避头尾

- 默认 `text-align: start`。不要 `text-align: justify`，中文在窄栏里两端对齐会拉出「河流」，字间出现一条条白色通道。
- 不要 `word-break: break-all`，英文单词、URL、版本号会被拦腰切断。需要断长串时用 `overflow-wrap: anywhere` 或 `overflow-wrap: break-word`。
- 避头尾交给浏览器：`line-break: strict` 阻止行首出现 。，、）」》 等标点，也阻止行尾出现（「《 等。默认 `normal` 已处理常见情况，标题与窄栏再开 strict。
- 标题不要用 `<br>` 硬断行。用 `text-wrap: balance`，在 390、768、1440 三个宽度检查断点落点；必须手动断时只在语义短语之间断，例如主谓之后。
- 表格、代码、长链接允许 `overflow-wrap: anywhere`，正文不允许。

### 7.4 假斜体与装饰

- 中文没有真斜体。`font-style: italic` 只会把字形机械倾斜，笔画变糊、重心偏移。中文强调用 600 字重、色块、下划线或引号。
- 下划线只给链接与文内重点，并且只用这一种装饰线：`text-decoration: underline; text-underline-offset: 0.2em; text-decoration-thickness: 0.06em;`。不要给中文加波浪线、点线、双线。
- 不要用 `text-shadow` 给中文做描边或发光，低分屏上会糊成一团。

### 7.5 数字与西文

- 数字与英文用半角。产品名大小写按官方写法：GitHub 不写 Github，iPhone 不写 Iphone。
- 中英混排时英文单词不拆行；整段英文加 `lang="en"`，合成语音与断词才正确。
- 页面根元素写 `lang="zh-CN"`。lint 的 `html-lang` 与 `cjk-font-stack` 都会查。

## 8. 常见错误

```css
/* 1 标题与正文同字号，只靠 700 撑层级 */
h2 { font-size: 16px; font-weight: 700; }        /* 反例 */
h2 { font-size: 24px; font-weight: 600; }        /* 正例 */
/* 2 正文行高 1.2 */
body { line-height: 1.2; }                       /* 反例 */
body { font-size: 16px; line-height: 1.75; }     /* 正例 */
/* 3 中文标题拉宽字距 */
.hero h1 { letter-spacing: 0.3em; }              /* 反例 */
.hero h1 { letter-spacing: 0; }                  /* 正例 */
/* 4 用 0.75rem 当全局基准 */
html { font-size: 12px; }                        /* 反例 */
html { font-size: 100%; }                        /* 正例 */
/* 5 行高写在布局容器上，整棵子树继承 */
.card { line-height: 1.2; }                      /* 反例 */
body { line-height: 1.75; } h2 { line-height: 1.25; }  /* 正例 */
/* 6 正文 max-width: 100% 铺满容器，1440 宽一行 90 多个汉字 */
.article p { max-width: 100%; }                  /* 反例 */
.article p { max-inline-size: 34em; }            /* 正例 */
```

**7. 用 `<br>` 硬断行**

- 反例：`<h1>把复杂留给系统<br>把简单留给用户</h1>`。390 宽时断成两行半，换一个宽度就要再维护一套断点。
- 正例：放进 `<h1>` 并加 `text-wrap: balance`，在 390、768、1440 三个宽度检查断点落点。
